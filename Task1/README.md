# Задание 1

### Пояснение

#### Стратегия масштабирования и отказоустойчивости
В качестве стратегии выбрано горизонтальное масштабирование HPA — каждый сервис, развернутый в Kubernetes, может автоматически масштабироваться на основе метрик нагрузки.
Это позволяет системе гибко адаптироваться к всплескам трафика.
Для повышения отказоустойчивости приложение развёрнуто в двух зонах доступности. В каждой зоне — независимый Kubernetes-кластер,
что обеспечивает изоляцию и минимизирует влияние сбоя одной зоны на другую. 
Такой подход надёжнее, чем растянутый кластер, так как снижает сетевые риски между зонами.

#### Балансировка нагрузки
На входе установлен Load Balancer, который равномерно распределяет трафик между двумя зонами. 
Балансировщик регулярно выполняет health-check в каждой зоне. При недоступности одной из зон
— выполняется автоматический фейловер на вторую зону.

#### Фейловер-стратегия
Фейловер реализован на нескольких уровнях:
Внешний балансировщик выполняет переключение между зонами при отказе на основании health-check.
Kubernetes-кластеры автоматически перезапускают упавшие поды.
База данных автоматически переключается на реплику при недоступности мастера.
